# L3 scripts

## Path-B inventory and final-state packages

### Deterministic geometry package

When a workflow has already established the Cartesian lattice, species/site
records, and magnetic representatives, use `prepare_geometry.py` to render the
repeated `cell.str`, `unit_cell.str`, and single-atom mode block in one new
directory. Its manifest is factual: it does not discover symmetry, choose
representatives, or infer a primitive cell. It rejects non-finite coordinates,
species-id/element mismatches, inactive representatives, and output-directory
reuse. Review structure mapping and physical representative choice separately.

The manifest is JSON with `lattice_angstrom`, `sites`, `species`, `spin_values`,
`representatives`, and positive `tolerance_angstrom`. Each species is
`{"element":"Fe","z_value":26}`; each site is an Angstrom Cartesian position
with a one-based `species_id` and matching element; each representative names an
active species and an exact reference-cell position. Optional `reference_cell`
and integer positive-determinant `relation` are checked with
`structure_mapping.py` before publication. The output receipt binds the manifest
hash and generated bytes. A new output directory is mandatory.

The generated `cell.str` explicitly declares
`AtomicCoordinatesFormat NotScaledCartesianAng`; this matters because the PASP
coordinate reader defaults to Bohr when the declaration is absent. The explicit
`unit_cell.na` and Angstrom blocks follow `Latticemodel/src/io_utils.f90`
`write_structure` and `read_input.F90::read_unit_cell_str` (source inspected
2026-10-10; portable scripts do not import that tree). The in-memory FDF parse
checks mode shape only; symmetry, chemistry, primitive choice, SOC and the PASP
supercell relation remain scientific review responsibilities.

### Deterministic dependency audit

After conversion and before fitting, run `check_dependencies.py` once over the
complete train and selection matrices. It excludes the target column, keeps the
first numerically independent feature column, and emits a receipt plus a
`Fitting_Set_Term_Skip.txt` using original feature numbers. It covers matrix
shape, finite values, dependency grouping, and row accounting; it does not prove
that a physical interaction is zero, choose a scientific tolerance, validate
PASP's internal renumbering, or replace native handoff/output review.

Run it with explicit tolerances, for example
`python3 check_dependencies.py --conversion /work/convert/conversion.json
--root /work/dependency-audit --rtol 1e-10 --atol 1e-12`. The conversion receipt
must hash the train/selection matrices and their original-ID lists; the script
also checks disjointness from the declared test IDs and never opens a test
matrix. Its affine replay records an intercept and coefficients for every
skipped original column, so constants and multi-column relations are handled
without correlation or eigensolver special cases. The receipt reports
`rank_with_offset`, pivot evidence and exact residual tolerances; it does not
claim a spectral condition number or native PASP column numbering. Compose the
original-column skip file with the actual native reduction mapping before a fit.

Use `prepare_path_b_inputs.py` directly on the supplied directory. It discovers
`OUTCAR.<id>`, `<id>.OUTCAR`, and numbered `<id>/OUTCAR` together, preserving IDs
(including gaps). Duplicate IDs, duplicate resolved sources, missing numbered
OUTCARs, changed species order/counts, incomplete final magnetization axes,
nonfinite values and singular lattices fail before publication. `--pattern` is an
explicit flat-file filter, not an ID-renumbering rule. Single symbolic IDs remain
supported for extraction; full-study conversion/batching requires integer IDs.

```sh
python3 /path/to/skills/knowledge/scripts/l3_effective_hamiltonian/prepare_path_b_inputs.py /data/final-dft --output-dir /work/path-b --normalize-magmoms
```

Choose normalization from the task's spin convention. Moment magnitude variation
alone does not invalidate a direction-only Hamiltonian. Output uses the final
lattice/position blocks and final complete x/y/z magnetization tables (or x-only
collinear tables), with a `source_identity.json` per ID and `manifest.json` listing
all IDs, raw final TOTEN, source hashes and output hashes. Direct coordinates use
row-vector `fractional = Cartesian @ inverse(lattice)`, including skew cells.
The source files are not modified; a new output directory is required. Publication
occurs after all samples parse. Interruption may leave files but no passing receipt.

This is extraction, not a DFT convergence/atom-mapping certificate. Independently
inventory the expected corpus, verify convergence and reconcile its energy table
with final TOTEN. A supplied POSCAR reference must match every OUTCAR's species
order/counts. Retain direction uncertainty near zero active moments. The optional
`--primitive-cells` Energy.dat output retains its **legacy numeric first-line
divisor header**; full-study `study_contract.py` must instead use the supplied raw
energy table or an explicitly generated headerless table, plus a separately justified
`energy_divisor`. Never skip a numeric first row using `energy_header: one`.

For supported single-atom spin/full-or-off SOC inputs use `method6.py prepare`.
The request paths resolve relative to the JSON request. Supply the **actual
successful run's** `PASP.input`, native `local_mode_PM.dat`, full log and recorded
exit file from that same run directory, not an earlier draft. If exit evidence
was not captured, it is missing evidence; do not manufacture it from a marker.

```json
{"basis_input":"basis-run/PASP.input",
 "basis_file":"basis-run/local_mode_PM.dat", "basis_log":"basis-run/log.out",
 "basis_exit_code_file":"basis-run/exit.code", "soc":"off", "policy":"reuse",
 "dependencies":{}}
```

```sh
python3 /path/to/skills/knowledge/scripts/l3_effective_hamiltonian/method6.py prepare --request /work/method6-request.json --root /work/method6-template
```

SOC is an explicit record of the established basis, not a new modeling choice.
The preparer uses `prepare_l3.py`'s FDF reader and spin checks, preserves unrelated
settings and mode definitions, and changes only the three runtime controls:
method 6, explicit read/rebuild policy, and `nstr_random 1`. Shadowed copies are
removed and ordinary includes flattened. Native contiguous `ipara_gb` IDs and
nonzero actual modes are required. Extra keyword-read files must be explicitly
listed in `dependencies` and reviewed; arbitrary dependencies, redirected FDF,
restricted SOC, nonspin modes and `local_mode.poscar_files` are outside coverage.
The receipt pins the source/run/native-basis hashes and changed declarations.


Ask the controller to return each staged directory's `log.out`, real `exit.code`,
`local_mode_PM.dat` and `distortion.ene_symbol`. Probe the first explicit ID before
authorizing the remainder; failure blocks the dependent batch. Then collect the

```sh
python3 /path/to/skills/knowledge/scripts/l3_effective_hamiltonian/method6.py collect --root /work/encodes-attempt-1
```

Only when runtime is **explicitly assigned to the helper**, `batch` may run it.
Extend the stage request with an explicit `command` argv list (the maintained local
launcher, optionally wrapped in the supplied timing runner), positive
`timeout_seconds`, and positive integer `jobs`. Use verified absolute launcher
paths. The script adds no MPI environment, scheduler, executable path, scientific
parameters, sample range or retry policy. `run_method6_batch.sh --request ...` is
the portable wrapper for this interface; its old environment-variable API is retired.
The first ID is a real probe; failure records the others as `not_run`. Successful
probes permit the remainder at the selected bounded concurrency. Timeouts terminate
the launcher's process group; logs, actual exit codes and failures remain visible.
Both routes require the complete inventoried ID set in a new batch directory.

expanded modes, finite ordered features matching the native width, unchanged
runtime inputs and **byte-identical native PM**, not equal counts or FDF text used
as a basis. They create `encoding_identity.json` from the persisted pre-run hashes
and successful feature hash, `result.json`, `status.tsv`, and `batch.json` with
explicit conversion sample entries. Resolve those entries relative to the batch
root when constructing the full-study manifest; use actual native PM for
`basis_file`, and require source identity. No post-hoc input hashing substitutes
for the pre-run capture. All IDs must pass before conversion/fitting.

Do not assume `read_interaction T` is broken for every basis: a recorded failure
with malformed modes did not establish that, and another basis reused successfully.
On a failed probe inspect effective mode syntax, actual modes, file identity and
the full failure location before changing physics or runtime. Permit at most one
explicit `policy: rebuild` probe from the same successful basis input after a
diagnosed reuse failure, in a new attempt directory. Rebuild must reproduce the
full native PM bytes; count agreement alone is insufficient. If byte identity
cannot be established, stop and investigate parameter ordering/polynomials with
independent evidence rather than substituting a template hash, weakening the check,
or repeatedly changing SOC, stack/environment settings or unrelated files.

Warnings are preserved with line locations and require contextual review; the
mechanical runner does not mark a warning-containing encode accepted. For a
documented benign build warning, use a bounded source-backed review of that exact
run and keep the warning and disposition outside the frozen report; do not remove
it from logs or repeatedly rerun the scientific workflow. Geometry, convergence,
model suitability, residuals, physical labeling, periodic aliasing and independent
scientific acceptance remain outside these checks. Existing conversion, fitting
handoff, full prediction reconstruction and test-isolation checks remain mandatory.
Reuse passing mechanical receipts only for unchanged inputs, and consolidate the
uncovered scientific checks after deliverables are frozen. Native helper delegation
and the state machine's terminating review/finish policy still apply.

## Bounded spin-input preparation (before the basis run)

Use `prepare_l3.py spin` for the supported **single-atom spin, method-2 mode**
format once the representative sites and Cartesian coordinates in Angstrom are
established. This is an input preparer, not a primitive/symmetry finder. It requires
an explicit SOC policy (`full` or `off`); there is no material, cutoff or spin-scale
default. Existing `number_of_species`, `Z_values`, and `Spin_values` must agree.

The request contains only the chosen policy and symmetry representatives, e.g. this
**synthetic schema illustration**, not a recommended physical model:

```json
{"soc": "full", "representatives": [
  {"species": 1, "position_angstrom": [0, 0, 0]}
]}
```

```sh
python3 /path/to/skills/knowledge/scripts/l3_effective_hamiltonian/prepare_l3.py spin --input /work/candidate/PASP.input --request /work/spin-request.json --root /work/spin-prepared
python3 /path/to/skills/knowledge/scripts/l3_effective_hamiltonian/prepare_l3.py check-spin --input /work/spin-prepared/PASP.input --soc full
```

It writes x/y/z modes per representative with the leading method `2`, derived count,
one species line, six finite numbers, no gap after the count, and exactly one blank
line between modes. An explicit full/off request replaces **all** old mode/SOC
headers and removes all `local_mode.special_SOC` blocks, including shadowed aliases
in ordinary includes. This changes the basis: use it **before** basis generation;
a change to an established basis invalidates dependent encodes and fitted models.
Restricted SOC, displacement/collective/lamp modes require the reference-backed
route and are not covered by this command. Never use full/off as a way to bypass a
requested restriction.

The supported FDF reader resolves `%include filename` against the intended runtime
working directory (the input file's parent), not the including file's parent. It
uses first declarations, ignores case and `_ . -` in labels, and reports source file
hashes and replaced declaration locations. Output is a self-contained, flattened
FDF: unrelated records and block contents are retained in order (line endings are
normalized to LF). It does **not** merge arbitrary run directories or stage files
read through non-include keywords. Conditional label redirects (`<`), external
block redirects, quoted tokens, nested directives and unnamed block ends are
explicitly unsupported; cycles/missing includes fail before output. Other explicit
keywords and file dependencies still need the field inventory and preflight.
Do not interpret a successful parse as validation of all fields in the file.

`spin-preparation.json` is a mechanical receipt, with remaining scientific checks
listed explicitly. Unchanged receipt-covered counts, numeric shapes and mode/SOC
format do not need another verifier. Representatives, coordinate/structure mapping,
spin conventions, basis suitability and real basis outputs remain uncovered. In
particular, inspect actual **nonzero modes and parameters**, warnings and expected
outputs; exit zero/graceful completion alone did not catch a missing method header
in the training run.

## Fitting data staging (after full conversion, before any fit)

Fitting uses PASP `Model Fitting_one_order`; external Python may check predictions
and metrics, but must not replace the requested PASP fit. Every rehearsal, pilot fit,
or lambda/basis comparison uses the same frozen study split. A diagnostic encoding
sample is not permission to form a new fitting split. Prior test access must remain
disclosed even if its model is discarded; a later clean package cannot undo it.

Use `prepare_l3.py fit-data` to stage the checked full training and selection rows
from a `study_contract.py convert` receipt. Checkpoint that receipt's SHA256 when
conversion succeeds, then supply it explicitly. Paths below are illustrative:

```sh
python3 /path/to/skills/knowledge/scripts/l3_effective_hamiltonian/prepare_l3.py fit-data --conversion /work/conversion/conversion.json --split /work/split.json --receipt-sha256 <saved-sha256> --lambdas /work/lambdas.json --root /work/fit-data
```

`lambdas.json` is an explicit nonempty JSON list of finite factors greater than 1
in the chosen evaluation order, not a built-in schedule. Each `LAMBDAS(I)` is a
successive multiplication factor for the regularization/search threshold, not an
additive ridge penalty. Factors below 1 decrease the threshold; 1 leaves it
unchanged. Both are rejected for this automatic growing-threshold search. The
factors need not increase from one row to the next: each factor must exceed 1.
The script derives the feature width from the conversion receipt, but writes
`min(feature_width, 150, floor(1.5 * train_row_count))` as the independent
`Nc_p_s` retained-parameter cap on every row of `Fitting_Set_Lambda.txt`.
Candidate feature width is not the retained-parameter cap. It verifies the split
hash/full-ID partition, train/selection
hashes, row maps, counts, equal widths and finite numbers, then writes:
`Fitting_Dataset.txt`, `Fitting_Data_for_prediction.txt`, their `.ids.json` maps,
`Fitting_Set_Lambda.txt` and `fit-data.json`. It neither opens nor stages the test
matrix. A new output directory is mandatory; preserve interrupted/failed attempts.

This is **not yet a runnable fitting package**. Add a reference-checked
`PASP.input`, real structure/includes and positional `Fitting_Settings.txt` before
promotion. Set keep/skip flags deliberately; the template's enabled keep-list is
not a current-basis choice. Active flags need current-numbered files. These settings
remain outside script coverage. Keep pristine conversion matrices outside runs:
`I_CHECK_DATA` can rewrite them. Preserve mappings and reproduce train/selection
predictions from frozen coefficients before a single test evaluation. The receipt
cannot prove split creation time, prior test isolation, convergence or model quality.

Immediately before each automatic PASP fitting run, check the actual completed
package (including any edited lambda file), and persist its JSON output:

```sh
python3 /path/to/skills/knowledge/scripts/l3_effective_hamiltonian/prepare_l3.py check-fit --input /work/fit-run/PASP.input
```

`check-fit` reads the actual train/selection matrices, `Model`, and every lambda
row. It rejects candidate widths over `floor(1.5 * train_rows)`, any round cap
over `min(150, floor(1.5 * train_rows))` or the feature width, nonfinite values,
and lambda factors at or below 1. It returns artifact hashes and the effective
caps. A failed check blocks runtime; repair in a new attempt directory. This
check does not replace the dependency/skip-term check or native handoff checks.

### Original source identity for spin/OUTCAR studies

For scientific spin/OUTCAR conversion set `require_source_identity: true` and
`source_energy_atol` to a tolerance justified by Energy.dat precision (raw eV,
before division). Add `original_id` if a sample was renumbered, plus
`source_identity` and `encoding_identity` paths to every sample entry. IDs may
remain nonconsecutive; renumbering is not required. Each record resolves its own
paths relative to its JSON file. Example records for one original sample:

```json
{"original_id": 7, "outcar": "7/OUTCAR",
 "structure": "final/7/distortion.pos", "magnetic_state": "final/7/distortion.MAGMOM"}
```

```json
{"original_id": 7, "structure": "run/7/distortion.pos",
 "magnetic_state": "run/7/distortion.MAGMOM",
 "sha256": {"structure": "<actual pre-run structure hash>",
            "magnetic_state": "<actual pre-run magnetic input hash>",
            "basis": "<actual pre-run local_mode_PM hash>",
            "features": "<actual successful-run ene_symbol hash>"}}
```

The first is the independently established source ledger; prepare its final-state

illustrative hash placeholders with hashes captured before PASP (inputs/basis) and

against the captured hashes. Thus rewriting final MAGMOM after initial-state encoding,

`source_identity_checked`. Missing required records fail before output publication.

the canonical magnetic file was correctly extracted. Those checks remain required.
Path A can reuse initial features only with final-state agreement evidence.
Unsupported/nonspin studies retain explicit provenance review; legacy manifests
still work but return `source_identity_checked: false` without this evidence.

## Native fitting parameter handoff

Use `fit_handoff.py` before interpreting coefficients or passing an L3 model to
MC/MD. It needs Python 3.10+ and sibling `study_contract.py`, no PASP/compiler.
It reads the selected native `*_LM.txt`, the corresponding standard fit report's
leading physical term table/B coefficients, same-basis `ipara_gb` declarations,
pristine full-width train/selection matrices and PASP `_data.txt`/`_data2.txt`.
Internal XM is not an export map. Example manifest:

```json
{
  "basis_file": "basis/local_mode_PM.dat",
  "lm_file": "fit/Report_fitting_best_predict_function_GRAD_21_LM.txt",
  "fit_report": "fit/Report_fitting_best_predict_function_GRAD_21.txt",
  "prediction_atol": 1e-9, "coefficient_atol": 1e-12,
  "datasets": [
    {"name": "train", "matrix": "conversion/train.txt",
     "predictions": "fit/Report_fitting_best_predict_function_GRAD_21_data.txt"},
    {"name": "selection", "matrix": "conversion/selection.txt",
     "predictions": "fit/Report_fitting_best_predict_function_GRAD_21_data2.txt"}
  ]
}
```

Tolerances above are examples, not scientific error thresholds: choose from output
precision/units and preserve their rationale. For an existing candidate add
`"j_file": "candidate/J_best.dat"`. All matrices contain nfeature columns and target
last. Prediction rows must be exactly ordinal, target, estimate, uncertainty, error.

以下是 legacy adapters 的历史布局说明；全量研究使用上面的 full-study 和 method-6 contract：
- 基于当前 L3 服务器实跑，`0.generaterandomspin/input/` 会直接生成原始 `*.ene_symbol` 与 `*.vasp_MAGMOM`；如果脚本模板仍假设源文件位于 `test/` 子目录，需要先按真实目录布局修正再使用。
- `get_ene.sh` 当前同时支持两类 Step 4 目录布局：
  - 编号子目录：`1/OUTCAR`、`2/OUTCAR`、...
  - 扁平结果集：`1.OUTCAR`、`2.OUTCAR`、...；这对批量 `OUTCAR` 的路径 B 起点尤其常见
- `convert_data.py` / `convert_data.f90` 读取 `convert_info.txt` 的前三行作为训练集数、测试 / 预测集数和每个 DFT 超胞中包含的原胞个数；第三行是能量归一化除数，不是 `unit_cell.str` 的原胞原子数。它们要求 `ene_symbol/<start-id>.ene_symbol` 开始的连续编号文件存在，并跳过 `Energy.dat` 第一行标题后按同样编号顺序读取能量。
- 例如 `unit_cell.str` 有 32 个原子、`cell.str` / POSCAR / OUTCAR 是 64 原子且对应 2 个原胞时，`convert_info.txt` 第三行应写 `2`，不是 `32`。若 DFT 能量已经预先按原胞归一化，则需要明确使用 `convert_data.py --no-energy-divide`，而不是把第三行改成原胞原子数。
- `Energy.dat` 的样本编号本身没有固定必须从 0 或 1 开始；硬要求是 `Energy.dat`、`ene_symbol/<id>.ene_symbol` 和转换脚本的起始编号完全一致，并且当前选择的样本编号连续。
- `convert_data.py` 按 `Energy.dat` 第一列的 sample id 建表，因此 `Energy.dat` 行顺序可以乱序，只要没有重复编号且所需编号都存在；但未修改的 `convert_data.f90` 是按文件行位置顺序读取并忽略第一列编号校验，乱序 `Energy.dat` 会造成能量和 `ene_symbol` 错配。
- 生成 `convert_info.txt` 时，如果用户没有指定切分，默认按 90/10 拆分当前可用连续样本：`Ntrain=floor(0.9*N)`，`Ntest=N-Ntrain`。例如 800 个样本应写为 `720` 和 `80`，不要默认写成 `800` 和 `0`。
- 如果当前样本编号是从 `0` 开始的连续编号，例如某些扁平 `results/<id>.OUTCAR` 目录，可在 `convert_data.py` 中使用 `--start-id 0`，不必先手工重编号。
- 优先使用 `convert_data.py`，因为它不依赖 Fortran 编译器或 Intel MPI 运行库。示例：`python3 convert_data.py --workdir .`
- `convert_data.f90` 保留为原始 example 逻辑来源；复制来的 `convert_data` 二进制依赖 Intel MPI 运行库（如 `libmpifort.so.12`），通用本地 shell 可能无法直接运行。未修改的 `convert_data.f90` 默认打开 `ene_symbol/1.ene_symbol`，并以 1-based 样本序列读取；若当前数据是 0-based，必须改用 `convert_data.py --start-id 0` 或显式改写 Fortran 起始编号逻辑，不能直接套旧二进制。
- `convert_data.py` 只负责把全部 `ene_symbol` 特征与能量拼接起来，不应根据某个旧 example 的拟合输入列数主动删除或跳过特征。
- 如果后续拟合目录中的 `Fitting_Dataset.txt` 在 PASP 运行后列数减少，先检查拟合阶段 `log.out` 是否出现 `NEED TO REWRITE DATA`，以及 `Data_Special_Properties_*.txt` 是否记录成比例或冗余变量；不要把这种 Step 6 数据检查重写误认为 Step 5 转换脚本的问题。

`extract_magmoms.py` 常见用法：

- 比较 VASP 最终磁矩方向是否仍和输入 `vasp_MAGMOM` 逐原子近似平行：
  - `python3 extract_magmoms.py sample/OUTCAR --reference ../0.generaterandomspin/vasp_MAGMOM/1.vasp_MAGMOM --show-all`
- 从 `OUTCAR` 直接导出路径 B 所需的 `distortion.MAGMOM`：
  - `python3 extract_magmoms.py sample/OUTCAR --distortion-out distortion.MAGMOM`

`rebase_unit_cell.py` 常见用法：

- 只验证当前 `unit_cell.str` 是否能通过已确认的 unit-cell → `cell.str` 关系矩阵映射到 `cell.str`：
  - `python3 rebase_unit_cell.py --cell cell.str --unit unit_cell.str --relation '2 0 0;0 1 0;0 0 1'`
- 如果已确认需要把 primitive 轴序从旧的 `x,y,z` 改成新的 `y,z,x`，同时重排基矢和原子坐标：
  - `python3 rebase_unit_cell.py --cell cell.str --unit unit_cell.str --relation '2 0 0;0 1 0;0 0 1' --reorder-axes y,z,x --output unit_cell.rebased.str`
- 如果候选 `unit_cell.str` 的基矢已经是目标轴向，但原子坐标仍被错误写成 `y,z,x`，只修复原子坐标分量。例如要把当前 `(y,z,x)` 坐标还原为 `(x,y,z)`，使用 `z,x,y`：
  - `python3 rebase_unit_cell.py --cell cell.str --unit unit_cell.str --relation '2 0 0;0 1 0;0 0 1' --reorder-atom-coords z,x,y --output unit_cell.fixed.str`
- 不要把 `--relation` 的矩阵直接写进 PASP `%block SuperCell`。如果 `cell.str` 已经是目标超胞，PASP `%block SuperCell` 通常应省略或保持单位阵。
- 这个脚本不负责决定 primitive cell 或物理轴向。使用前必须已有用户确认、read-only structure subagent 结论、PASP 分析结果或其他可核查来源。
- 通过标准是报告 `PASS: cell.str is compatible with unit_cell.str under the provided relation`。若报告 `FAIL`，不得把候选 `unit_cell.str` 提升为正式 input，也不得派生 run 或提交。
- 同时做对比并导出，若存在逐原子方向不一致会以非零退出码返回：
  - `python3 extract_magmoms.py sample/OUTCAR --reference 1.vasp_MAGMOM --distortion-out distortion.MAGMOM`

补充说明：
- `--reference` 同时支持 `MAGMOM= ...` 形式的 VASP 输入文件，以及逐行 `x y z` 的 `distortion.MAGMOM`
- 默认把模长小于 `0.1` 的向量视为非磁性；可用 `--min-norm` 调整
- 默认用 `cos(theta) >= 0.95` 判定“方向近似平行”；可用 `--cos-threshold` 调整
- 如果只在 `OUTCAR` 中找到单个磁矩分量块，脚本会按 collinear 模式处理，并提示输出向量被写成 `(m, 0, 0)`

`prepare_path_b_inputs.py` 常见用法：

- 仅凭单个 `OUTCAR` 整理一个路径 B 输入包：
  - `python3 prepare_path_b_inputs.py sample.OUTCAR --output-dir path_b_inputs`

- 如果额外有 `POSCAR`，可把它作为更稳定的物种顺序 / 原子数参考：
  - `python3 prepare_path_b_inputs.py sample.OUTCAR --poscar-reference POSCAR --output-dir path_b_inputs`

- 从扁平 `results/<id>.OUTCAR` 目录批量整理路径 B 输入包：
  - `python3 prepare_path_b_inputs.py results --poscar-reference results/POSCAR --output-dir path_b_inputs`

- 如果只有批量 `OUTCAR`、没有单独保存的 `POSCAR`，也可以直接批量整理：
  - `python3 prepare_path_b_inputs.py results --output-dir path_b_inputs`

- 同时从批量 `OUTCAR` 生成共享 `Energy.dat`：
  - `python3 prepare_path_b_inputs.py results --poscar-reference results/POSCAR --output-dir path_b_inputs --primitive-cells 9`

补充说明：
- 该脚本会为每个样本写出独立子目录，例如 `path_b_inputs/17/distortion.pos` 和 `path_b_inputs/17/distortion.MAGMOM`
